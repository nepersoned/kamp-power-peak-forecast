> 또한 **예측오차가 크게 발생하는 생산조건**과 **최대전력 피크가 발생하는 주요 조건**을 분석하고,
> **생산일정 또는 설비가동 시점 조정을 통한 피크전력 저감방안**을 제안하시오.

## 5. 성능 끌어올리기 실험

> 아래 표는 **공장인원 누수가 있던 상태**의 탐색 기록이다. 어떤 레버가 효과가 있었는지의 방향 참고용이며, 수치는 재계산이 필요하다.

|---|---|---|---|

### 예측 오차의 바닥 (누수 제거 후)
- 레짐 전환 LightGBM을 시드만 바꿔 5번: 테스트 MAE 6.56~6.78 (평균 6.68)
- **1시간 전 실측까지 입력으로 줘도 MAE 6.16** → 하루 전 예측과 차이 약 0.5
- 한 시간 안의 15분 값 편차가 평균 6.1 → 현재 오차가 이 노이즈 크기와 같음
- 남은 개선 여지는 평상시가 아니라 **휴무 후 재가동일**, **가동 개시 피크 과소예측**(08~11시)에 있다

| 전일 실측 | 0.316 | 0.21 | 0.49 |
| 제안 모델 일최대 예측 | 0.778 | 1.00 | 0.69 |
| 전용 분류기(보정 확률) | 0.692 | 0.64 | 0.65 |

- 평일 일최대가 모두 183~204에 몰려 190이 분포 한가운데 걸린다. **평일끼리 가를 정보가 입력에 부족**하다. 제안 모델의 경보 임계값(검증에서 결정)은 144로, 사실상 "가동 평일 전부 경보"와 같다.
- 시간 단위 판정은 어떤 방법도 정밀도 0.3 미만.
- 기준값 민감도: TAU=180이면 F1 0.98, 200이면 0.24.

### 불확실성
- P90 상한 실제 포함률 83% → 분할 컨포멀 보정 후 97%

### 피크 저감 시뮬레이션 (모델 기반 가상 결과)
예측 상위 2시간 생산의 일부를 같은 날 저부하 시간으로 이동(일 총량 보존):
| 이동 비율 | 평균 일최대 | 190 초과 시간 |
|---|---|---|
| 0% | 173.9 | 5 |
| 30% | 173.7 | 6 |
| 50% | 173.3 | 4 |

- **생산량 이동은 사실상 효과가 없다.** 누수 제거 전의 "7 → 2시간" 효과는 인원 피처(=전력 역산값)를 통해 생긴 가짜였다.
- 전력은 생산량보다 **가동 여부(on/off)와 가동 시각**에 반응한다. 경쟁 저장소(zongseung)도 같은 결론이며, 효과적인 레버는 가동 시각 이동이었다. → 강화학습 행동을 "가동 시각 이동" 중심으로 설계

### 해석
- **SHAP 상위**: 직전 가동일 동시각 피크·전력 → 가동 종료 이후 여부 → 생산량(±1시간 평균) → 전주 동시각 → 가동 종료 시각. 오프셋 포함으로 예측값과 정확히 일치하도록 분해
- **상호작용 상위**: 휴일 × 가동 종료 이후, 월 × 생산량, 직전 가동일 전력 × 피크
- **DiCE 반사실**: 예측 ≥ 185인 테스트 5시간 모두 해를 찾았지만, 목표수요 아래로 내리려면 해당 시간 생산을 중앙값 **88%** 줄여야 한다 → 생산량 조절은 약한 레버
- **누수 CV 시연**: 무작위 K-fold MAE 11.24 vs 복사 그룹 묶음 16.43 (약 32% 과소평가)
- 그림 11종: 데이터 개요, 레짐별 프로파일, 테스트 예측, 시간대별 오차, SHAP 중요도·요약·의존도·상호작용·FN/FP 사례, 일 단위 위험 판정, 저감 예시

## 8-2. 문헌·기법 조사 선별과 배정 (9/30)

세미나 메모(의사결정 학습, LLM 기반 시계열, 행렬분해·최적화)와 문헌 조사 보고서에서 이 데이터·이 대회에 쓸 만한 것만 골랐다. 기준은 세 가지다. ① 데이터 크기(원본 학습 약 1,800행, 텍스트 없음)에서 돌아가는가, ② 평가표 장에 수치로 기여하는가, ③ 10/8까지 끝나는가.

**우선순위**: 필수 = 10/3 통합 전 반드시 / 권장 = 10/5까지 / 선택 = 여유 있을 때만

### 배진형 — 결정 쪽 (강화학습 트랙에 붙임)

| 항목 | 우선순위 | 내용 | 쓰이는 장 |
|---|---|---|---|
| **한전 기본요금 래칫 구조** | 필수 | 기본요금 적용전력 = 직전 12개월 중 동계(12·1·2월)·하계(7·8·9월)·당월 최대수요 중 최댓값. 데이터 최대 222가 1·3·6·7월에 이미 찍혀 있어 8~9월 피크 저감의 기본요금 한계가치는 0에 가깝다 → 보상·절감액은 전력량요금(TOU) 중심, "래칫 갱신 위험"은 별도 지표로. 요금 단가와 데이터의 전기요금(계절) 값(109.8/167.2/191.6) 대응은 2021 요금표로 직접 확인 | 4장 |
| **래칫 인지 MILP 부하이동 (predict-then-optimize)** | 필수 | 결정변수: 시간대별 생산 배분·가동 시각. 목적: TOU 전력량요금 + 기본요금 단가 × max(래칫값, 당월 피크) + 인건비(1.0/1.5배). 최대값은 보조변수로 선형화. OR-Tools/PuLP로 소규모. **강화학습의 가장 강한 비교 기준선**(기존 계획의 "탐욕 최적화" 자리) | 4장, 5장 |

| **TOU·피크·인건비 삼중 상충 시나리오 표** | 권장 | 저가 시간대로 몰면 피크가 오르고(배치 제조 MPC 연구), 야간·주말은 인건비 1.5배. "피크 X kW 저감 시 절감액 vs 추가 인건비" 표로 제시 | 4장 |
| **시나리오 기반 확률 최적화 (CVaR)** | 선택 | 오성민 트랙의 분위수·경로 시나리오를 MILP/강화학습에 넣어 최악 꼬리 비용까지 관리 | 4장, 5장 |
| **롤링 원점 평가 + 일 단위 부트스트랩 / Diebold-Mariano** | 권장 | 평가 틀 담당으로서 테스트 일수를 늘리고 모델 간 차이에 신뢰구간 부여(기존 계획의 부트스트랩 항목 확장) | 2장 |

### 오성민 — 예측 분포 쪽 (TabPFN 트랙에 붙임)

| 항목 | 우선순위 | 내용 | 쓰이는 장 |
|---|---|---|---|
| **Chronos-2 zero-shot (생산량 공변량 포함)** | 권장 | TabPFN과 같은 "사전학습 모델" 비교군. 공변량(생산계획)을 넣을 수 있는 버전만 의미 있음. 복제일 제거 후 평가 필수. TabPFN과 같은 재현성 조건(오프라인 가중치, 라이선스) | 2장, 5장 |
| **컨텍스트 길이 민감도 (7/14/28일)** | 권장 | 복제일을 빼면 실효 이력이 수십 일이라 사전학습 모델 성능이 컨텍스트 길이에 민감할 수 있음. TabPFN·Chronos-2에 함께 적용 | 2장 |
| **LightGBM 분위수 회귀 (τ = 0.5, 0.9, 0.95)** | 필수 | 결정 기반 평가용 분포 파일의 LightGBM 버전. 현재 P90만 있음 → 분위수 확장. (기존 계획상 배진형 담당이던 LightGBM 분포 파일을 오성민이 분위수 비교와 함께 맡는다) | 2장, 5장 |
| **적응형 컨포멀 예측 (ACI / AgACI)** | 권장 | 지금의 분할 컨포멀은 포함률 83% → 97%로 과보정. 분포 이동(9월 등)에 맞춰 보정량을 갱신하는 ACI로 90%에 맞추기. 근거: Gibbs & Candès(2021), Zaffran 외(2022) | 5장 |
| **피크 크기 + 시각 동시 확률 예측** | 권장 | 일 피크의 크기 분포와 **발생 시각**(시간대 블록 또는 15분 슬롯)의 확률분포를 분위수·경로에서 산출. 평가: 임계 초과확률의 Brier·신뢰도 곡선, PR-AUC, 피크 시각 오차와 ±1슬롯 적중률. 문헌상 크기와 시각을 함께 다룬 연구가 적어 차별점 | 3장, 5장 |
| **운영형태 세분화 (일 생산시간 군집)** | 권장 | 지금은 가동/휴무 2개 레짐. 일 생산시간(0 / 1–12 / 13–19 / 20h+) 또는 일 부하곡선 군집(K-means, 선택적으로 FPCA)으로 운영형태를 나누고 형태별 기준곡선을 비교. 1장 "공정 상태 해석"의 재료 | 1장, 2장 |
| **누수 분류 체계 정리 (모델 인포시트)** | 필수 | Kapoor & Narayanan(2023) 분류에 맞춰 우리 데이터의 누수를 정리: 공장인원·평균 항등식(예측 시점 불가 특징), 복제일(훈련·테스트 중복), 생산량 = 계획 가정(실적이면 누수). 1장 부록. 모든 지표를 "원본일 기준"으로 보고하는 원칙도 여기서 명시 | 1장 |
| **복제 그룹 블록 CV + 퍼지** | 권장 | 복제 그룹이 학습·검증에 걸치지 않게 묶고, 검증 블록 앞뒤로 시차 길이(168시간)만큼 퍼지. 근거: Bergmeir & Benítez(2012). 누수 시연 표(무작위 11.24 vs 복제 그룹 묶음 16.43)의 방법론 근거 | 1장 |
| **기호회귀(GP-SR) 비교** | 선택 | 양민호·최태종(2025, 스마트미디어저널 14(4))이 같은 과제(제조공장 최대수요 예측)에서 신경망보다 좋았다고 보고. 이 데이터셋일 가능성이 있어 **선행연구로 원문 확인**이 먼저. 확인되면 해석 가능한 수식 기준선으로 추가 | 2장, 1장(선행연구) |

- **인용 규칙**: 보고서에 인용하는 논문은 DOI·원문으로 재확인. 2026년 arXiv 논문은 보조 근거로만. 공개 저장소 수치는 검증 방식 차이를 명시하고 기준선으로만 인용.

### 쓰지 않는 것과 이유

| 항목 | 이유 |
|---|---|
| LLM 기반 시계열(LLMTime, Time-LLM), 시계열+텍스트 멀티모달(Time-VLM, semantic 페어링) | 이 데이터에 텍스트가 없고, 원본 약 1,800행으로 대형 모델을 붙일 근거가 없음. 수치 토큰화는 연산 관계를 못 다룬다는 한계도 세미나에서 지적됨 |
| TimesNet, LSTM-AE + XGBoost 등 딥러닝 | 데이터가 작아 과적합 위험이 크고 기간 내 튜닝 부담. 사전학습 모델(TabPFN·Chronos-2)로 대체 |

| 극값 이론(EVT/POT) | 피크 사례가 수십 건이고 산업 부하 적용 논문을 확보하지 못함 |
| 역최적화 기반 생산 스케줄 식별 | 생산계획이 이미 주어져 있어 불필요, 합성 데이터 기반 연구 |
| 외부 한국 공장 데이터(Lee 외 2022)로 일반화 검증 | 논문용. 대회 기간 내 범위 밖 |

## 9. 앞으로의 계획

### 역할: 강화학습 × TabPFN, 서로 보완하는 구조

두 트랙은 **"예측 분포를 만드는 쪽"과 "그 분포로 결정을 내리는 쪽"**으로 맞물린다.

```
오성민 (TabPFN)                           배진형 (강화학습)
하루 전 예측 분포 ─────── ① 시나리오 ──────▶ 실시간 수요 제어 환경
 (시간별 분위수)                             (예측 + 불확실성으로 에피소드 생성)
        ▲                                             │
        └────────── ② 결정 기반 평가 ─────────────────┘
          "어느 예측기를 써야 피크를 더 줄이나"로
          TabPFN vs LightGBM을 MAE 밖에서 한 번 더 비교
```

- **① 시나리오 공급**: TabPFN의 예측 분포(분위수)를 강화학습 환경의 불확실성으로 쓴다. 지금 환경 후보(LightGBM + 잔차 부트스트랩)와 비교할 수 있다.
- **② 결정 기반 평가**: 같은 정책을 LightGBM 예측으로 돌릴 때와 TabPFN 예측으로 돌릴 때의 피크 감소를 비교한다. 예측 오차(MAE)가 바닥이라 차이가 안 보이는 두 모델을 **"현장 결정에 얼마나 도움이 되나"**로 다시 가른다. 5장 차별성의 핵심 이야기다.
- ③ TabPFN이 불확실하다고 본 시간대(분위수 폭이 넓은 시간)는 강화학습 정책이 보수적으로 행동해야 할 구간이 된다. 3장 오류분석과 4장 운영 절차를 잇는 고리다.

**배진형 — 강화학습 트랙 (3장 피크 조건, 4장, 6장)**
- 피크 발생 조건 분석: 시각·요일·생산량·인원·계절별 190 초과 빈도. 강화학습의 상태·보상 설계 근거이자 3장 재료
- 실시간 수요 제어 환경(gym 인터페이스)
  - 상태: 현재 시각, 오늘 누적 최대 수요, 남은 생산량, 앞으로의 예측·분위수
  - 행동: 이번 시간 생산 비율(예: 100/70/40%)과 **가동 시각 이동**(설비 기동 지연). 전력은 생산량보다 가동 on/off에 더 반응하므로(경쟁 저장소 분석, 우리 DiCE 결과와 일치) 시각 이동이 핵심 레버. 미룬 양은 뒤 시간으로
  - 보상: −일최대 수요 − 생산 미달 벌점 − 계획 변경 비용
  - 제약: 일 생산 총량 완수, 시간당 생산 상한(관측 최대치), 가동 시간대 안에서만 이동
- **공장 부하 시뮬레이터**: 기저부하 + 생산 비례 + 가동 개시 램프 + 요일·교대 + 잔차 분포. 데이터로 보정하고 LightGBM 환경과 교차 확인
- 비교 기준선: 무조치 → 고정 규칙(예측 ≥ 190이면 30% 미루기) → **래칫 인지 MILP**(8-2절) → 강화학습(PPO 등)
- **한전 산업용(을) 고압A 요금 반영**: 계시별 전력량요금 + 기본요금 + 래칫. 보상과 절감액 계산에 사용(래칫 때문에 기본요금 절감은 작을 수 있음)
- 모델 간 차이 부트스트랩 신뢰구간, 누수 감사 테스트(항등식·시차·복사 그룹)
- 최대수요전력 기본요금 기준 비용 환산, 전날 경보 → 당일 제어 운영 절차
- 최종 예측 모델 정리(레짐 전환 LightGBM), 평가 항목 추가(운전 상태 전환 구간, 생산조건별 오차)
- README·requirements·제출 zip

**오성민 — TabPFN 트랙 + 통계 시계열 기준선 (1장, 2장 비교, 3장 예측 오류, 5장 불확실성)**
- TabPFN 하루 전 예측: 같은 분할·같은 피처로 레짐 전환 LightGBM과 비교
  - 휴무일은 기존처럼 중앙값 기저부하, 가동일만 TabPFN으로 대체하는 버전도 시험
  - CPU 추론 시간 확인. 학습 문맥이 크면 원본 행만 쓰거나 나눠서 처리
- 예측 분포: 시간별 분위수(10·50·90%)를 뽑아 실제 포함률 확인, 컨포멀 보정 결과(81% → 95%)와 비교
- 평가 항목: 전체 MAE + 운전 상태 전환 구간 + 피크 시간대(08~11시) 편향 + 분위수 예측은 **CRPS·포함률**
- **가이드북 기준 모델 재현**(SimpleRNN, 과거 168시간): 비교표에 "가이드북 기준" 칸으로 추가. 1시간 앞 예측이라 조건이 다름을 명시
- **SARIMAX 기준선** (2장 비교표의 "전통 시계열 모델" 칸)
  - 하루 주기(24) SARIMA + 외생변수: 가동 여부, 생산량, 인원, 요일·주간 푸리에 항 (주기 168을 직접 넣으면 너무 무거움)
  - 매일 자정에 다음 24시간을 예측하고 하루씩 미는 롤링 방식. 같은 검증·테스트 구간, 같은 표
  - 1~6월 복제 구간은 자기상관이 가짜라 원본 구간 위주로 학습하고, 복제 구간 포함 여부를 비교
  - 정전일(8/28~29)은 결측·더미로 처리. `statsmodels` 설치 필요
  - 기대: 전주 값(테스트 8.3)과 LightGBM(6.3) 사이. "머신러닝이 전통 시계열보다 얼마나 나은가"의 근거
- 변수 정의와 데이터셋 가이드북 요약(1장). TabPFN 입력 피처를 고르며 변수를 들여다보게 되므로 함께 맡는다
- 재현성: 가중치를 오프라인으로 불러오는 방법, 라이선스 확인

**채택 기준 (TabPFN)**: 아래 중 하나라도 수치로 보이면 채택, 아니면 "시도했으나 기여 없음"으로 기록
- 전환 구간 또는 피크 시간대에서 LightGBM보다 뚜렷이 낮은 오차
- 보정 없이 명목 포함률(90%)에 가까운 분위수
- 검증과 테스트 **양쪽에서** LightGBM과 섞었을 때 개선
- 결정 기반 평가(②)에서 피크 감소가 더 큼

**TabPFN이 막힐 경우**(설치·속도·라이선스): 오성민 님은 파생 피처·날 단위 증강으로 전환하고, 재가동일·피크 시간대 같은 약점을 겨냥한다.

### 인터페이스 (두 트랙이 주고받는 파일)
- `outputs/forecast_dist_{모델}.csv`: `timestamp, target, q10, q50, q90` (target은 power 또는 peak15, 검증·테스트 구간 전체)
- 오성민 → 배진형: TabPFN 분포 파일. 배진형 → 오성민: 같은 형식의 LightGBM 분포 파일(비교 기준)
- 강화학습 환경은 이 파일 하나만 읽어 시나리오를 만든다. 예측기를 바꿔 끼우기만 하면 결정 기반 평가가 된다

### 함께 지킬 규칙
- 평가는 원본 구간(7월 이후)만. 무작위 교차검증 금지
- 증강은 학습 구간 안에서만. 복제일 포함/제외를 비교해 기록
- 테스트 구간(8/16~9/14)은 선택에 쓰지 않는다
- 새 피처는 `src/features.py` 함수로, 증강은 학습셋 변환 함수로 붙여 `run_all.py`의 같은 표에서 비교
- 모든 실험은 "바꾼 것 · 검증 점수 · 채택 여부" 한 줄로 기록. 기각한 실험도 보고서 재료

### 위험 요소
- **테스트 구간에 휴무·재가동이 없음** → 증강·파생 피처의 기여가 테스트 MAE에 안 보임. 전환 구간 평가 항목으로 보여줄 것
- **튜닝 과적합** → 복잡한 모델을 더할 때 같은 일이 반복될 수 있음
- **생산계획 가정** → 방어 근거(일 단위 계획 7.2, 잡음 ±50%에도 6.9) 보고서에 포함
- **저감 효과는 모델 기반 가상 결과** → 실측 아님과 행동 범위 제한 명시
- **타깃 누수 재발** → 새 피처를 넣을 때마다 항등식·시차 감사를 통과해야 함. 공장인원은 절대 쓰지 않는다
- **경쟁 저장소가 이미 공개** → 데이터 진단·요금 반영은 다른 팀도 함. 강화학습 실시간 제어와 결정 기반 평가로 차별화
- **요금 절감 과장 위험** → 래칫 때문에 8~9월 피크 감소가 기본요금을 거의 줄이지 못할 수 있음. 절감액은 요금표로 직접 계산해 보수적으로
- **공개 저장소** → 마감 전 공개 상태. 보고서·발표자료에는 저장소 링크·계정명을 넣지 않는다(블라인드)
